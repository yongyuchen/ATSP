# Reconstructed ftv90–ftv160 instances and the 27-instance ATSPLIB set

This note documents how the ATSPLIB set used in the paper was extended from the
19 files distributed by TSPLIB to 27, and records the cross-solver checks that
validate the eight reconstructed instances. Raw results are in
`data/ftv_extra/`; the corresponding expected values are in
`data/expected_atsplib.json` (27 rows).

## 1. Construction

TSPLIB does not ship `ftv90`–`ftv160` as separate files. Per TSPLIB95 §3.3 they
are the prefix subproblems of `ftv170`: instance `ftvX` consists of the leading
`X+1` rows and columns of the 171-city full matrix in `ftv170.atsp`, so its
dimension is `n = X+1`. The eight files in `instances/` were generated by that
rule.

| Instance | n | Published optimum |
|---|---:|---:|
| ftv90 | 91 | 1579 |
| ftv100 | 101 | 1788 |
| ftv110 | 111 | 1958 |
| ftv120 | 121 | 2166 |
| ftv130 | 131 | 2307 |
| ftv140 | 141 | 2420 |
| ftv150 | 151 | 2611 |
| ftv160 | 161 | 2683 |

## 2. Independent verification of the reconstruction

Three independent exact solvers were run on each prefix, without being given the
published optimum. Concorde solves the symmetric `2n`-node expansion with
`M = UB + 1`; the ATSP optimum is recovered as `expanded_cost − n·M`. CPLEX-DFJ
and SCIP-DFJ solve the asymmetric formulation directly. All three return the
published optimum on all eight instances (8/8 each).

Concorde detail (`data/ftv_extra/concorde_results.json`):

| Instance | n·M | recovered ATSP optimum | published optimum |
|---|---:|---:|---:|
| ftv90 | 146510 | 1579 | 1579 |
| ftv100 | 186446 | 1788 | 1788 |
| ftv110 | 223221 | 1958 | 1958 |
| ftv120 | 268499 | 2166 | 2166 |
| ftv130 | 309422 | 2307 | 2307 |
| ftv140 | 348975 | 2420 | 2420 |
| ftv150 | 402566 | 2611 | 2611 |
| ftv160 | 432607 | 2683 | 2683 |

The raw `match` field in that JSON compares the *expanded* cost before the
`n·M` shift and is therefore `false`; the table above is the decoded comparison.

## 3. Results of the certifying implementation

Default caps, 60 s wall clock (`data/ftv_extra/ftv8_ours.json`). None of the
eight instances is certified; the solver returns a tour but issues no
certificate, as expected for these structured flow-shop instances.

| ftv90 | 91 | 1579 | 1609 | +1.90% | no | 2.84 |
| ftv100 | 101 | 1788 | 1845 | +3.19% | no | 2.35 |
| ftv110 | 111 | 1958 | 2010 | +2.66% | no | 2.28 |
| ftv120 | 121 | 2166 | 2218 | +2.40% | no | 2.17 |

A 600 s sensitivity run on four representative instances
(`data/ftv_extra/results_600s.json`) still reports `proved=False`: each hits the
2 × 10⁶ search-node cap within 3–22 s, so the 60 s limit is not the binding
constraint.

## 4. Structural statistics

`|Ã|/n²` is the fraction of non-basic arcs whose reduced cost is within the
budget `Δ = UB − Z_AP`; `UB` is the shipped (patching + Or-opt) incumbent.
Statistics are computed by `scripts/atsplib_structure.py` and stored in
`data/ftv_extra/structure_results.json`.

| Instance | n | Δ/Z_AP | \|Ã\|/n² |
|---|---:|---:|---:|
| ftv90 | 91 | 8.79% | 61.39% |
| ftv100 | 101 | 10.48% | 76.32% |
| ftv110 | 111 | 9.06% | 70.13% |
| ftv120 | 121 | 9.53% | 78.15% |
| ftv130 | 131 | 7.12% | 61.00% |
| ftv140 | 141 | 7.52% | 66.78% |
| ftv150 | 151 | 6.22% | 57.95% |
| ftv160 | 161 | 4.92% | 43.17% |

Calibration: recomputing `ftv170` gives `|Ã|/n² = 48.91%`, matching the value in
the paper's ATSPLIB table. Adding the eight prefixes lowers the uncertified
lower end from 48.9% to 43.2%, so the certified range (10.8–23.6%) and the
uncertified ATSPLIB range (43.2–97.0%) remain disjoint.

The marker is a joint statistic of the instance and the incumbent, not a
classifier or a routing threshold. Its sensitivity to four different incumbents
is analysed in `docs/R4_INCUMBENT_SENSITIVITY.md`.
